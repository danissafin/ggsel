# GGSEL Seller Bot + Telegram Mini App v8.5

## Новое: названия товаров в чатах + умная очередь поддержки

- **В чатах вместо UUID/технического кода отображается реальное название купленного товара.** Источники: связанные заказы, история продаж, партии и (при необходимости) один запрос каталога GGSEL. Если реального названия нет ни в одном источнике, показывается честное «Товар по заказу №…», а не выдуманное имя.
- Исправлен источник проблемы: UUID больше не сохраняется как `product_name` при новых заказах и обработке webhook. Существующие чаты получают название при следующей загрузке, данные актуализируются в SQLite.
- **Предложение готового решения:** если последняя жалоба содержит известный код ошибки (например, `0xc004f050`) и в базе знаний есть точная подходящая инструкция для купленного товара, в диалоге появляется кнопка «Вставить ответ». Перед отправкой продавец проверяет текст; бот никогда не отправляет его автоматически.
- **Умная очередь:** фильтры «Требуют ответа» и «Срочные»; обнаружение сообщений о возвратах, ошибках активации и открытых проблемных заявках. Это простые объяснимые правила, НЕ ИИ и НЕ автоматическая отправка ответов.
- Уведомления Telegram только при **нулевом** остатке сохранены из v8.4.
- Новых Railway Variables нет. БД и Volume сохраняйте при обновлении.

### Проверка

1. Распакуйте v8.5 и замените файлы репозитория. Не удаляйте Railway Volume.
2. Дождитесь **Active** в Railway, затем полностью закройте Mini App и откройте снова.
3. В «Чатах» дождитесь первой загрузки: при отсутствии заголовков потребуется один запрос каталога GGSEL.
4. Убедитесь, что названия настоящие, а фильтры очереди работают. Если не удаётся сопоставить товар, будет показан номер заказа вместо UUID.
5. Нет возможности гарантировать восстановление названия для старых покупок, отсутствующих в доступной истории заказов и каталоге API.

### Ограничение

Сопоставление названия опирается на доступную историю заказов и идентификатор оффера. Если у заказа нет `item_id`, имя не было сохранено в истории продаж и GGSEL не отдаёт другие данные, программа не сможет установить название достоверно. В этом случае технический ID будет скрыт и будет показана безопасная подпись.

# GGSEL Seller Bot + Telegram Mini App v8.4

## Что нового в v8.4: Telegram только при нулевом остатке

- **Уведомления о малом остатке полностью отключены** независимо от `LOW_STOCK_DEFAULT` и индивидуальных порогов товара.
- Сообщение в Telegram отправляется **только если фактический остаток равен нулю**; несколько таких товаров объединяются в одну отправку.
- Повторное сообщение по тому же товару не отправляется, пока запас не станет положительным и затем снова не упадёт до нуля.
- Текущее состояние `monitor_stock` в Railway Volume сохраняется при обновлении — уже зарегистрированные нулевые остатки повторно не рассылаются.
- Низкие остатки **по-прежнему отображаются в Mini App** для удобства контроля, но Telegram не тревожат.
- Это изменение касается автоматического мониторинга остатков. Уведомления из явно подключённого служебного чата GGSEL остаются отдельной функцией.

## Встроенный мониторинг GGSEL v8.3

Теперь бот умеет **фоном проверять остатки всех товаров** и отправлять сообщения в Telegram без открытия Mini App. Это собственный мониторинг через Seller API, **не** дословная пересылка чата «Уведомления» на сайте.

- Малый остаток не вызывает уведомления в Telegram.
- Когда остаток доходит до нуля — тревожное сообщение «товар закончился».
- После пополнения состояние автоматически сбрасывается, поэтому следующее снижение снова вызовет уведомление.
- Несколько событий объединяются в одно сообщение Telegram, чтобы не засорять чат.
- При недоступности Telegram состояние события не фиксируется, и доставка будет повторена при следующей проверке.
- Снимок остатков, история обработанных сообщений и настройки хранятся в SQLite на Railway Volume.
- Фоновая проверка по умолчанию — **каждые 5 минут**, с задержкой первого запуска около 20 секунд после старта приложения. Для работы процесс Railway должен быть запущен и не спать. Если сервис останавливается при простое, нужен внешний Cron/постоянно работающий сервис.

### Как настроить

1. Установите v8.3 поверх прежней версии, сохранив Railway Volume и действующие переменные `BOT_TOKEN`, `OWNER_ID`, `GGSEL_API_KEY` и `DB_PATH`.
2. Откройте **Ещё → Система → Telegram-уведомления GGSEL**.
3. Включите оповещения об остатках и нажмите **«Проверить сейчас»**. Первая проверка может прислать сводку товаров, у которых уже **0 ключей**.
4. Порог малого остатка влияет только на интерфейс Mini App; Telegram-уведомление приходит строго при остатке **0**.
5. Чтобы проверить доступность служебных чатов, нажмите **«Найти чаты в API»**. Это показывает только идентификаторы и краткие метаданные **непрочитанных** переписок — наличие чатов «Поддержка» и «Уведомления» не гарантируется.
6. Если обнаружен достоверный ID служебной беседы, выберите его и сохраните. После этого новые сообщения будут пересылаться, только если GGSEL действительно отдаёт эту переписку через официальный API. **Старые сообщения при первой синхронизации не пересылаются.** Не привязывайте обычные чаты покупателей вместо служебных, иначе уведомления продублируются.

### Railway Variables

```env
GGSEL_MONITOR_ENABLED=true
GGSEL_MONITOR_INTERVAL_SECONDS=300
LOW_STOCK_DEFAULT=3
# Необязательно, только для защищённого внешнего расписания:
CRON_SECRET=длинный_случайный_секрет
```

Новые переменные **необязательны**: мониторинг включён по умолчанию. `GGSEL_MONITOR_INTERVAL_SECONDS` ограничен 60–3600 секундами. Для отключения фоновой проверки задайте `GGSEL_MONITOR_ENABLED=false` (ручная кнопка «Проверить сейчас» остаётся доступна).

Защищённый endpoint для запуска по внешнему расписанию (опционально):

```
GET https://ВАШ-АДРЕС/cron/ggsel-monitor?secret=ЗНАЧЕНИЕ_CRON_SECRET
```

Не публикуйте `CRON_SECRET` и не используйте открытую ссылку. При пустом `CRON_SECRET` endpoint недоступен. Не настраивайте одновременно слишком частые внешние проверки и внутренний монитор без необходимости: SQLite предотвращает одновременный запуск, но лишние обращения к API не нужны.

### Ограничение GGSEL API

В опубликованной документации метод `GET /api_sellers/api/debates/v2/chats` описан как получение списка непрочитанных чатов. **Отдельный API для служебных диалогов администрации и системных уведомлений не подтверждён.** Поэтому прямая пересылка сообщений из них — экспериментальная функция, не включённая автоматически. Диагностика не использует парсинг закрытых страниц, пользовательские cookies или неофициальные endpoint-ы.

### Проверки

Проверены синтаксис Python/JavaScript, миграция БД, защита фоновых запусков, сценарии переходов «норма → низкий остаток (без сообщений) → ноль → пополнение», отсутствие повторных сообщений, повтор после ошибки Telegram и работа с новыми/старыми сообщениями через имитацию ответов GGSEL. Тестов с настоящим GGSEL или Telegram-аккаунтом не выполнялось. На Railway после развёртывания обязательно проверьте вкладку «Система» и отправку одного безопасного тестового оповещения.

## Главное в v8.0

### Расширенный поиск по всему кабинету

Кнопка поиска в верхней панели теперь ищет одновременно по:

- товарам и остаткам;
- заказам, email и аккаунтам покупателей;
- полной локальной истории переписок;
- точному проданному или загруженному содержимому;
- поставщикам и партиям;
- проблемным обращениям и кодам ошибок;
- базе знаний;
- заметкам к заказам и клиентам;
- журналу ошибок API.

Обычный запрос без команд ищет сразу во всех разделах. Например:

```text
Office 2021
```

Поддерживаются фильтры:

```text
товар:"Office 2021" остаток:<5
статус:проблемный ошибка:0xc004f050
поставщик:Китай после:2026-07-01
тип:заказ прибыль:<100
ключ:XXXXX-XXXXX-XXXXX-XXXXX-XXXXX
заметка:"повторная проверка"
```

Доступные команды:

- `тип:` — товар, заказ, чат, ключ, поставщик, партия, проблема, инструкция, ошибка или заметка;
- `товар:` — название или ID товара;
- `заказ:` — номер заказа;
- `клиент:` — email, аккаунт или идентификатор клиента;
- `ключ:` — точный поиск содержимого по HMAC-отпечатку;
- `поставщик:` и `партия:`;
- `статус:`, `метка:`, `заметка:`, `ошибка:`, `категория:`, `приоритет:`;
- `остаток:`, `цена:`, `сумма:`, `прибыль:` с условиями `<`, `<=`, `>`, `>=`, `=`;
- `после:` и `до:` для ограничения даты.

Значения с пробелами заключаются в кавычки. Несколько обычных слов и фильтров объединяются по принципу «всё должно совпасть».

### Навигация из результатов

Результат ведёт сразу в соответствующее место:

- товар — в карточку оффера;
- заказ или заметка к заказу — в карточку заказа;
- клиент — в объединённую переписку;
- проданный ключ — в связанный заказ, а складской — в товар;
- проблема — в отфильтрованный центр обращений;
- инструкция — в базу знаний;
- поставщик или партия — в раздел закупок;
- ошибка API — в центр здоровья системы.

### Удобство поиска

- примеры команд находятся прямо в окне поиска;
- активные фильтры показываются отдельными чипами;
- сохраняются последние шесть запросов на устройстве;
- поиск открывается кнопкой, клавишей `/` или сочетанием `Ctrl/Cmd + K`;
- при недоступности каталога GGSEL локальные разделы продолжают искать, а интерфейс показывает предупреждение.

## Возможности v7.0

### Замена содержимого в один клик

Из карточки заказа или переписки можно:

1. предварительно выбрать свободную позицию нужного оффера;
2. увидеть маску нового содержимого и текущий остаток;
3. указать причину;
4. подтвердить замену;
5. зарезервировать позицию через GGSEL;
6. отправить её покупателю в последнюю активную ветку;
7. сохранить замену, аудит и связь с проблемным обращением.

Полное значение замены используется только во время операции. В локальной базе сохраняются HMAC-отпечаток и маска.

### Закупки, поставщики и партии

При пополнении можно указать:

- поставщика;
- закупочную цену единицы;
- валюту;
- курс к рублю;
- дату закупки;
- гарантию поставщика;
- комментарий.

Mini App создаёт партию и связывает загруженное содержимое с себестоимостью.

### Реальная прибыль

Раздел **«Закупки и прибыль»** показывает:

- начисление после комиссии площадки;
- себестоимость проданного содержимого;
- чистую прибыль;
- маржинальность;
- долю заказов, для которых известна себестоимость.

Кнопка **«Обновить 20 заказов»** загружает последние продажи и карточки заказов, индексирует доступное проданное содержимое и обновляет расчёт.

### Центр проблемных заказов

Поддерживаются статусы:

- новый;
- диагностика;
- ждём клиента;
- замена;
- решено;
- закрыто.

Для обращения сохраняются приоритет, категория, ошибка, причина, заметка, заказ, товар и клиентская переписка.

### Автоматическое распознавание проблем

Входящие сообщения проверяются на:

- ошибки активации и коды вида `0x...`;
- запрос возврата;
- неполученный товар;
- проблемы установки;
- жалобы и признаки негативного отзыва.

Коды ошибок относятся к категории активации и не смешиваются с возвратами.

### Мастер диагностики

Есть готовые сценарии для Windows, Office и общих проблем. Мастер формирует последовательность проверки и предлагает подходящую статью из базы знаний.

### База знаний

Можно хранить и отправлять инструкции по продукту, категории и кодам ошибок. При первом запуске создаются стартовые статьи для Windows и Office. Текст статьи вставляется в ответ покупателю перед отправкой.

### Массовые проблемы

Если за заданный период набирается несколько одинаковых сигналов, создаётся инцидент. В разделе **«Качество»** отображаются товар, ошибка, число обращений и период наблюдения. Владельцу отправляется Telegram-предупреждение.

### Качество товаров и поставщиков

Для товара рассчитываются:

- продажи;
- уникальные проблемные заказы;
- замены;
- негативные отзывы;
- доля заказов без зарегистрированных проблем.

Для поставщика показываются количество загруженных, проданных и заменённых позиций, а также показатель качества на основе замен.

### Ежедневный отчёт

Отчёт дополнен:

- чистой прибылью при известной себестоимости;
- проблемными обращениями;
- заменами;
- диалогами без ответа;
- рекомендациями.

## Ограничения, о которых важно знать

- Автоматическая замена возможна, только когда GGSEL возвращает доступную позицию оффера с её значением и для заказа найден действующий диалог покупателя.
- Архивирование позиции выполняется GGSEL как фоновая операция. Mini App регистрирует задачу, проверяет отсутствие явной ошибки и показывает её дальнейший статус в центре операций.
- Полная история старых проданных значений восстанавливается только для заказов, в карточках которых GGSEL отдаёт это содержимое. Новые загрузки индексируются заранее.
- Чистая прибыль точна только для проданных позиций, связанных с партией и себестоимостью. Старые заказы без такой связи показываются как заказы с неизвестной себестоимостью.
- При начислениях не в рублях необходимо задать валюту и курс к рублю в разделе **«Закупки и прибыль»**.

## Railway Volume

Подключите постоянный Volume по пути:

```text
/data
```

Он хранит SQLite, CRM, партии, себестоимость, историю замен, статьи, ошибки и резервные копии.

## Обновление с v7.0

1. Замените файлы репозитория файлами v8.0.
2. Не удаляйте Railway Volume и старую SQLite-базу.
3. Новые Railway Variables для поиска не требуются.
4. Дождитесь статуса Railway **Active**.
5. Полностью закройте Telegram Mini App и откройте заново.

Новые таблицы и столбцы создаются автоматически. Существующие заказы, чаты, заметки и настройки сохраняются.

## Проверка после развёртывания

1. Откройте **«Закупки и прибыль»** и задайте валюту/курс.
2. Добавьте поставщика.
3. Пополните тестовый товар, указав себестоимость и партию.
4. Нажмите **«Обновить 20 заказов»**.
5. Откройте тестовый заказ и проверьте расчёт прибыли.
6. Создайте проблемное обращение и запустите диагностику.
7. Перед реальной заменой проверьте предварительный просмотр и маску содержимого.

## Проверка расширенного поиска

После обновления откройте поиск в верхней панели и последовательно проверьте:

```text
Office
статус:проблемный
тип:заказ прибыль:<100
ключ:ваше_точное_содержимое
```

Точный поиск ключа работает только для содержимого, которое уже было проиндексировано при загрузке, замене или чтении карточки заказа. Полное значение ключа в SQLite не сохраняется.


## v8.1 — удобство и скорость

- Быстрый поиск защищён от гонок запросов: устаревшие ответы больше не заменяют новые результаты.
- Кратковременный (20 секунд) кеш поисковых ответов в оперативной памяти браузера; запросы с `ключ:` не кешируются.
- Обновление текущего раздела показывает процесс и блокирует повторное нажатие; ошибки отображаются пользователю.

- Название открытого раздела отображается в шапке.
- Клавиши на компьютере: `Alt+1…5` — основные разделы, `Alt+R` — обновление, `/` и `Ctrl/Cmd+K` — поиск.
- Улучшены фокус, размеры нажатий и работа на узких экранах.
- Серверные эндпоинты, схемы базы, GGSEL-токены и переменные Railway не изменены.


## v8.6 — Диспетчер поддержки (новая функция)

В чате нажмите **«✦ Разобрать обращение»**. Система собирает сводку по клиенту,
последнему заказу, повторению кода ошибки, истории открытых проблемных обращений,
похожим ошибкам у других покупателей и локальной базе знаний. Показывает
пошаговые проверки и черновик ответа, который можно вставить вручную.

**Безопасность:** функция только читает уже сохранённые данные, ничего не
отправляет покупателю и не списывает ключи. Похожие случаи подсчитываются
по локально зарегистрированным проблемным обращениям, а не по всей истории GGSEL.
Новых переменных Railway или миграций базы не требуется.
